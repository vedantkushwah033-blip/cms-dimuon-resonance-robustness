## Provenance and non-finite kinematic validation

The baseline CLI now records, when available, the local input size, ROOT tree entry count, required branch types, Python and key package versions, and optional SHA-256 checksum. Enable the checksum for a local file with `--sha256-input`; this reads the file once before the analysis, so it adds I/O overhead. For remote URLs the checksum is intentionally unavailable in this version.

Histogram accounting now separately records pairs below the requested mass range, inside the histogram range, above the range, and with non-finite calculated masses. This makes the counts auditable rather than silently dropping invalid values.

The Awkward-array invariant-mass helper now clamps only negative mass-squared values within a floating-point tolerance. Non-finite kinematic inputs are preserved as non-finite instead of being silently converted to zero mass. A new test covers this failure mode, and the integration test independently verifies the input SHA-256 and full pair-count accounting.

## Full-data acceptance and conservation audit hardening — 2026-10-26

The metadata audit now rejects partial processing for a full-data parity claim: `events_read` must equal the reference event count, `events_processed` must equal `events_read`, and `max_events` must be absent or at least the full dataset size. It also requires candidate pair categories (in-range, below-range, overflow, and non-finite) to sum exactly to the opposite-charge pair total, with all counts represented as nonnegative JSON integers. Relational guards reject impossible cut-flow counts, including opposite-sign events exceeding exactly-two-muon events and opposite-charge pairs exceeding selected events.

The audit additionally compares the ROOT reference's `histogram_entries_including_flow` to its opposite-sign event count. Regression tests cover partial runs, broken pair accounting, malformed count types, impossible count relationships, and reference histogram/cut-flow disagreement.

## Reference histogram flow-count conservation — 2026-10-26

A further metadata-integrity check now requires the reference ROOT histogram's regular-bin total, underflow, and overflow counts to sum exactly to `histogram_entries_including_flow`. This is distinct from checking that ROOT's fill-entry count matches the opposite-sign cut-flow: a corrupted or inconsistently recorded flow-bin field could otherwise evade the latter check. The new invariant rejects malformed counts, including booleans masquerading as integers, and has regression tests for both an inconsistent sum and a boolean count.

The code and regression tests are committed; the latest CI result must be checked before this change is described as validated. This check still does not replace an actual CMS-data run or independent review of generated reference artifacts.


## Comparator-report internal consistency — 2026-10-26

The metadata audit now checks the comparator's discrepancy summary as well as its exact-parity boolean. A passing audit requires zero differing bins, zero total absolute count difference, and zero maximum absolute count difference; these fields must also be nonnegative JSON integers. This guards against a stale, manually edited, or internally inconsistent comparison report whose boolean claims parity despite nonzero discrepancy metrics.

A regression test intentionally supplies that contradictory report and verifies that the audit fails. CI for the newest code/test commits must be checked before calling this change validated. Real-data processing and exact parity on the official CMS input remain outstanding.


The first CI run after adding the discrepancy-summary checks exposed two valid-audit fixtures that had not been updated with the comparator's three new required metrics. The failures were in test setup, not evidence of a production audit false negative: the fixtures omitted `differing_bin_count`, `total_absolute_bin_count_difference`, and `maximum_absolute_bin_count_difference`. Both fixtures now explicitly record zeros for exact-parity cases. The corrected fixture commits are `d059d6a3` and `6eb0ec9e`; their new CI runs must pass before the latest audit change is considered validated.
