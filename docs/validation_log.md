## Defects found and corrected during validation

1. The synthetic ROOT writer creates additional physical branches for jagged-array counters, so the initial test's exact branch count was too strict. The assertion was changed to validate a minimum expected count while testing named branches and report contents directly.
2. The inspector reports missing candidate fields in alphabetical order; the test expectation was corrected to match that deterministic order.

These failures were useful test-fixture corrections, not evidence of a CMS-data result. They are recorded rather than hidden.

## Reference-alignment changes and latest test run

The baseline script now defaults to the public example's exactly-two-muon selection, opposite-charge pair requirement, 30,000 bins, 0.25–300 GeV mass range, and logarithmic axes. The public reference is the [CMS Open Data dimuon example](https://github.com/cms-opendata-analyses/DimuonSpectrumNanoAODOutreachAnalysis), whose implementation uses ROOT RDataFrame and ROOT four-vectors. Our implementation uses Uproot/Awkward and NumPy, so it is an independent implementation rather than a verified reproduction.

A test initially failed after the mass lower bound was changed to a positive value for the log x-axis; the old test still passed zero. The test input was updated to use 0.25 GeV, and event-limit accounting was corrected to use the number of input events read.

## Provenance and non-finite kinematic validation

The baseline CLI now records, when available, the local input size, ROOT tree entry count, required branch types, Python and key package versions, and optional SHA-256 checksum. Enable the checksum for a local file with `--sha256-input`; this reads the file once before the analysis, so it adds I/O overhead. For remote URLs the checksum is intentionally unavailable in this version.

Histogram accounting now separately records pairs below the requested mass range, inside the histogram range, above the range, and with non-finite calculated masses. This makes the counts auditable rather than silently dropping invalid values.

The Awkward-array invariant-mass helper now clamps only negative mass-squared values within a floating-point tolerance. Non-finite kinematic inputs are preserved as non-finite instead of being silently converted to zero mass. A new test covers this failure mode, and the integration test independently verifies the input SHA-256 and full pair-count accounting.
